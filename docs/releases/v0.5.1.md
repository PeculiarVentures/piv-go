# v0.5.1

This patch expands the YubiKey 6 preview signing profiles using additional
slot-specific hardware checks and records follow-up results for YubiKey NEO,
YubiKey 4 and YubiKey 5C NFC.

## Capability profiles

- For the exact `YubiKey 5C NFC - Enhanced PIN` / `6.0.0.alpha.8` / PIV
  `0.0.1` preview tuple, P-256 ECDSA is reported in the four main slots and
  `82`–`95`. Ed25519 and ML-DSA profiles include only the additional slots
  tested for each algorithm.
- Exact NEO `3.4.9` / PIV `1.0.4`, YubiKey 4 `4.2.8` / PIV `4.2.8`, and
  YubiKey 5C NFC `5.4.3` / PIV `5.4.3` profiles cite the applicable additional
  hardware evidence. YubiKey 4 profiles split some documented P-384 and
  RSA-2048 operations by slot so that evidence is attributed only to the
  tested slots. Consumers persisting profile IDs should refresh their snapshots.
- Device profiles do not prove the current private key or authorize its use.
  Live matching still requires current authoritative key metadata, which is
  unavailable on NEO and the tested YubiKey 4 firmware.

## Qualification limits

The [qualification record](../signing-qualification.md) lists the tested
slots, algorithms and parameters, including ECDH and RSA decryption observations.
The signing capability report does not describe ECDH or decryption.

The additional preview checks verified the card serial but did not independently
re-read its model, device firmware or PIV applet version. Those fields came from
the supplied session context. Other firmware versions, untested combinations,
and touch-enforced workflows are not qualified by those checks.

For this release, the production hardware signing suite was rerun on the
connected YubiKey 5C NFC with OpenSSL 3.6.3. The preview and NEO hardware
suites were not rerun on the final release source; their earlier results and
the provenance of the follow-up tests are recorded in the qualification record.
