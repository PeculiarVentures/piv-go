# v0.5.2

The YubiKey 6 preview signing profile no longer treats the slots sampled during
hardware qualification as an exhaustive allowlist. Ed25519 signing in `9a`,
for example, is now reported as supported when current key evidence and the
requested parameters match.

For the exact `YubiKey 5C NFC - Enhanced PIN` / `6.0.0.alpha.8` / PIV
`0.0.1` tuple, the existing RSA-2048/3072/4096, P-256/P-384, Ed25519 and
ML-DSA-44/65/87 signing profiles cover `9a`, `9c`, `9d`, `9e` and `82`–`95`.
The algorithm parameters, message and transport limits, current-key evidence
requirements and application authorization policy are unchanged. RSA-1024
remains unqualified. Other device or firmware versions do not automatically
inherit this preview profile.

The slot policy generalizes the sampled hardware results in the
[qualification record](../signing-qualification.md); it does not mean every
algorithm was tested in every slot. During release verification, the identified
preview card's existing Ed25519 key in `9a` matched the updated profile and
produced verified signatures for empty, ordinary and 4096-byte messages. The
test did not reset PIV or replace keys. The full destructive hardware matrix
was not rerun for this release.
