# v0.6.0

The YubiKey signing report now selects a separate YubiKey 6 preview family for
the exact inventory model `YubiKey 5C NFC - Enhanced PIN` with device firmware
`6.x.y.alpha.n` or `6.x.y.beta.n`. All such alpha/beta releases are covered:
`x` and `y` range from 0 through 255, and `n` is a nonnegative decimal iteration
without a single-byte or machine-integer limit. Components use ASCII digits
without leading zeros except for `0`. This includes earlier alphas, later
alphas and betas, and minor/patch versions beyond `6.0.0`.

Previously, preview profiles required the exact model / `6.0.0.alpha.8` / PIV
`0.0.1` tuple. The base family profile now remains available when `PIVVersion`
is missing or different. Supply actual device firmware separately from the PIV
applet version; the report does not discover either value. Other model names,
FIPS/Bio variants, malformed versions, other major versions, and production
firmware without an alpha/beta qualifier do not acquire preview profiles.

The family policy covers RSA-2048/3072/4096, P-256/P-384, pure Ed25519 and pure
ML-DSA-44/65/87 in `9a`, `9c`, `9d`, `9e` and `82`–`95`. Existing algorithm,
message and transport limits remain in effect, including the 0–4096-byte pure
message limit. RSA-1024 remains unqualified. Supported matching still requires
current authoritative key evidence and does not grant application authorization.

## Capability report migration

Consumers that persist, compare or allowlist capability reports must refresh
their snapshots and review these changes:

- Preview profile IDs move from `yubikey/qualified-6.0.0.alpha.8/` to
  `yubikey/6-preview/`. Profiles carrying exact hardware evidence also have an
  `/evidence-6.0.0.alpha.8` suffix. Do not interpret the old prefix as a stable
  key for the new family policy.
- Every preview profile carries `family-policy` evidence referencing
  [the family policy](../signing.md#yubikey-family-profiles). This explicitly
  generalizes sampled hardware results to the supported 6.x alpha/beta family;
  it does not mean each release, slot or parameter value was hardware-tested.
- Only the exact model / `6.0.0.alpha.8` / PIV `0.0.1` tuple adds evidence from
  [the qualification record](../signing-qualification.md), restricted to its
  inventoried operations and slots. Fixed named-hash operations and zero-salt
  PSS use `hardware-qualification`; sampled message/payload length intervals
  and positive-salt PSS intervals use `hardware-samples`. Raw ECDSA digests and
  other slots retain family policy alone. Interval evidence does not establish
  that every value in that interval was tested.
- The exact tuple's profiles are split into disjoint slot sets to preserve
  that provenance. Report profile counts and IDs therefore change even where
  supported operations remain the same. Match complete operation parameters
  and evaluate evidence explicitly instead of relying on profile position or
  assuming every supported profile is hardware-qualified.

No new hardware qualification is claimed for this release. The broader family
policy is a compatibility decision; the recorded hardware confirmations retain
their exact device, firmware, applet, slot and parameter scope.
